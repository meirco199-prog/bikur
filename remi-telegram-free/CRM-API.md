# חיבור CRM הביטוח לרמי — פרוטוקול

רמי (הבוט בטלגרם) מקבל מה-CRM את המשימות הפתוחות, מזכיר עליהן, ומחזיר ל-CRM מה שסומן כבוצע.
כל התקשורת היא HTTPS מה-CRM אל הבוט — הבוט לא פונה אל ה-CRM (שרץ במחשב ואינו נגיש מבחוץ).

כתובת הבסיס: `https://remi.meirco199.workers.dev`

## 1. חיבור (חד-פעמי)

1. ה-CRM מייצר **קוד חיבור** אקראי, 12–64 תווים מהסט `A-Za-z0-9_-` (מומלץ 24), ושומר אותו אצלו.
   ליצירה בטוחה: `secrets.token_urlsafe(18)` (פייתון) או `crypto.randomUUID()` בלי מקפים.
2. ה-CRM מציג את הקוד למשתמש, והמשתמש שולח לרמי בטלגרם: `חבר CRM <הקוד>`.
3. רמי שומר **רק SHA-256 של הקוד**, מוחק את ההודעה מהצ'אט ולא רושם אותה בהיסטוריה.
4. מעכשיו כל בקשה ל-API נושאת `Authorization: Bearer <הקוד>`.

ניתוק: המשתמש שולח `נתק CRM`. בדיקת מצב: `סטטוס CRM`. הפקת קוד חדש + `חבר CRM` חדש מחליפה את הישן.

## 2. סנכרון — `POST /crm/sync`

גוף הבקשה (JSON):

```json
{
  "snapshot": true,
  "ack": ["c1"],
  "tasks": [
    { "id": "c1", "client": "יוסי כהן", "title": "לחדש פוליסת רכב", "due": "2026-10-12" },
    { "id": "c2", "client": "דנה לוי",  "title": "להתקשר לגבי תביעה", "due": "" }
  ]
}
```

| שדה | הסבר |
|-----|------|
| `tasks[].id` | מזהה יציב של המשימה ב-CRM (מחרוזת, עד 64 תווים). אותו id = אותה משימה — סנכרון חוזר מעדכן ולא מכפיל. |
| `tasks[].client` | שם הלקוח — מופיע בטקסט המשימה ברמי. |
| `tasks[].title` | מה צריך לעשות (חובה). |
| `tasks[].due` | תאריך יעד `YYYY-MM-DD`, או ריק. עם תאריך עתידי — רמי שולח תזכורת **ב-9:00 בבוקר ביום היעד**. |
| `snapshot` | `true` = הרשימה היא **כל** המשימות הפתוחות ב-CRM; משימה של ה-CRM שחסרה בה נחשבת סגורה ב-CRM ותוסר מרמי. בלי השדה — רק הוספה/עדכון, בלי מחיקות (בטוח לשליחה חלקית). |
| `ack` | מזהים שה-CRM כבר טיפל בהם מתוך `completed` של התשובה הקודמת — כדי שלא יחזרו. |

תשובה (200):

```json
{ "ok": true, "added": 2, "updated": 0, "removed": 0,
  "completed": [ { "id": "c1", "status": "done" } ] }
```

`completed` = משימות שהמשתמש סגר **ברמי** ועוד לא אושרו: `done` (✅ בוצע) או `cancelled` (❌ ביטול).
ה-CRM אמור לסגור אותן אצלו, ובסנכרון הבא להוסיף את המזהים ל-`ack`.
כל עוד מזהה לא אושר, רמי לא מחזיר אותו לרשימה גם אם ה-CRM עדיין מחזיק אותו פתוח.

שגיאות: `401` — קוד שגוי / לא מחובר (התשובה כוללת `hint`); `400` — JSON לא תקין; `405` — לא POST.

## 3. בדיקת חיבור — `GET /crm/status`

מחזיר `{ "ok": true, "openTasks": N, "pending": [...], "lastSync": <ms> }` עם קוד תקין, אחרת `401`.
מתאים לכפתור "בדוק חיבור" ב-CRM.

## קצב מומלץ

סנכרון בלחיצת כפתור וגם אוטומטית כל 10–15 דקות כשה-CRM פתוח. אין חשש מקריאות תכופות
(מותר מאות משימות בבקשה, עד 500).

## מה המשתמש רואה

- ברשימת המשימות של רמי: `יוסי כהן — לחדש פוליסת רכב (עד 12/10)`, עם הכפתורים הרגילים ✅ / ❌.
- ב-9:00 ביום היעד: תזכורת `📋 יוסי כהן — לחדש פוליסת רכב (עד 12/10)`.
- סימון ✅ או ❌ ברמי מסיר את התזכורת ומועבר ל-CRM בסנכרון הבא.

## בדיקה מהירה (curl)

```bash
CODE='הקוד-שנשלח-לרמי'
curl -s -X POST https://remi.meirco199.workers.dev/crm/sync \
  -H "Authorization: Bearer $CODE" -H 'Content-Type: application/json' \
  -d '{"snapshot":true,"tasks":[{"id":"t1","client":"בדיקה","title":"משימת ניסיון","due":""}]}'
```
