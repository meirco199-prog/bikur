# Investment Strategy Lab — מעבדת אסטרטגיות השקעה (LAB.md)

**כתובת:** `/invest/lab/` (GitHub Pages) · **מנוע:** `invest-api/engine/lab/` · **נתונים:** ענף `lab-data` (נבנה ב-Actions) · **AI:** `POST /lab/parse` ב-`invest-api`

מערכת מחקר עצמאית לבדיקה היסטורית של כמעט כל אסטרטגיית השקעה/מסחר: בונה אסטרטגיות ללא קוד (תנאים מקוננים, דירוגים, כניסה/יציאה/גודל),
Backtesting כרונולוגי ללא look-ahead עם עלויות מלאות, השוואות, אופטימיזציה עם אימון/אימות/מבחן ו-Walk-Forward, מובהקות עם תיקון לריבוי ניסויים,
ו-AI שמתרגם בקשה חופשית להגדרה מובנית. **מחקר בלבד. אין מסחר. Backtest אינו תחזית. הצלחה היסטורית אינה הבטחה לרווח.**

## 1. בחירת הטכנולוגיה — ולמה לא React/Next + Python/FastAPI + Postgres

הדרישה המקורית הציעה React/Next.js, Python/FastAPI, Polars, PostgreSQL, Parquet ו-Redis. הבחירה בפועל שונה, מנומקת:

| שיקול | הצעה | מה נבחר | למה |
|---|---|---|---|
| מדיניות הריפו | bundler, npm, build | **HTML/CSS/JS כמו שהם**, ES modules | `CLAUDE.md` + `.ai/REVIEW.md`: הוספת build/npm היא BLOCKER. כל הריפו מתפרסם ישירות מ-`main`. |
| מנוע חישוב | Python/FastAPI על שרת | **JS טהור אחד** (`engine/lab/`) שרץ ב-Node (בדיקות, Actions), ב-Web Worker בדפדפן, וב-Cloudflare Worker | אותו קוד בדיוק בשלוש הסביבות = אין סטייה בין "מה שנבדק" ל"מה שרץ". אין שרת לתחזק/לשלם. מהירות: 20 שנה × 500 מניות × Top-10 יומי ≈ שניות בודדות. |
| אחסון היסטורי | Parquet + Postgres | **JSON compact לפי עשור** (`bars/SYM.decade.json`) בענף `lab-data`, נטען ל-Typed Arrays | אין DB לנהל; Git = גרסאות + CDN (raw.githubusercontent) חינם; Cache API בדפדפן. החיסרון: אין שאילתות חוצות-ניירות בצד השרת — לא נדרש, המנוע טוען את היקום לזיכרון. |
| הרצות ארוכות/רקע | Redis + Jobs | **Web Worker** (התקדמות, ביטול, שמירת תוצאות ב-IndexedDB) + **GitHub Actions** (`lab-data.yml`) לריצות מלאות שמפורסמות ל-`lab-data/results/` | מכסה את הדרישה (רקע, התקדמות, ביטול, שימוש חוזר) בלי תשתית חדשה. |
| ממשק | React/Next | מסכים כ-ES modules + הרכיבים של `invest/` (CSS, גרפים SVG) | עקביות עם האפליקציה הקיימת, RTL, כהה/בהיר. |

**מתי השיקול יתהפך:** Intraday מלא (מיליוני נרות) או יקום של כל המניות בארה"ב כולל נמחקות — אז נדרש אחסון עמודי (Parquet/DuckDB) ושרת.
הארכיטקטורה מפרידה בין שכבות (נתונים ← אותות ← סימולציה ← מדדים ← אופטימיזציה ← UI), כך שהחלפת שכבת הנתונים לא נוגעת במנוע.

## 3. כללי הסימולציה (מניעת הטיות — דרישה 10)

| הטיה | איך נמנעת | איפה |
|---|---|---|
| Look-ahead | האות של יום t מחושב אחרי הסגירה מנתונים ≤ t; הביצוע ביום t+1 (פתיחה/MOC/Limit/Stop). `same_close` קיים רק כאופציה מסומנת "אופטימית" והתוצאה מסומנת מוגבלת | `simulate.js` סדר הפעולות בראש הקובץ; בדיקת prefix-invariance ב-`lab-engine.test.mjs` |
| הרכב מדד של היום | חברות לפי מרווחי [מ-, עד) ליום; מניה שלא הייתה במדד ביום האות לא נבחרת | `data.js` `membersAt`, `lab-data.mjs` (fja05680) |
| Survivorship | חברי מדד היסטוריים ללא נתוני מחיר (נמחקו) נספרים ומדווחים; כיסוי < 90% → "מוגבל" | `Dataset.coverage`, `coverageBox` ב-UI |
| מחיר בלתי אפשרי | מילוי רק בפתיחה/בסגירה הרשמיים או ברמת סטופ/יעד/Limit אם הנר נגע בה; פער בפתיחה → מחיר הפתיחה (גם לרעה); שתי רמות באותו נר → סטופ | בדיקה "מחירים בלתי אפשריים" |
| פיצולים/דיבידנדים | כמות ומחיר כניסה מתואמים בפיצול; דיבידנד ב-ex-date (לונג מקבל, שורט משלם); אינדיקטורים על סגירה מתואמת, ביצוע על גולמי | `Series.adjOHL`, בדיקות פיצול/דיבידנד |
| עלויות | עמלת IBKR Fixed (0.005$/מניה, מינ׳ 1$, מקס׳ 1%) או נ"ב; החלקה ומרווח לכל צד; עמלות רגולטור במכירה; השאלה בשורט; ריבית מרג'ין | `commission`, `slipped`, `regulatoryFees` |
| נזילות | אין הנחת נזילות מעבר לנר; השתתפות במחזור לכל עסקה מוצגת; אפשר להגביל `maxVolumePct` | `participation` |
| מחיקה | פוזיציה פתוחה נסגרת בסגירה האחרונה הידועה, מסומנת | בדיקת "מניה שנמחקה" |
| ריבוי ניסויים | Bonferroni + Deflated Sharpe (Bailey & López de Prado) + רגישות + אימון/אימות/מבחן + Walk-Forward; אזהרות Overfitting | `optimize.js` |

**מה עדיין הנחה אופטימית ומסומן בדוח:** אין נתונים תוך-יומיים (סטופים על High/Low יומי; מגבלת הפסד יומי נמדדת בסגירה); MOC = קירוב; השאלה בשורט קבועה; אין margin call; סקטורים לפי הסיווג הנוכחי.

## 5. הפעלה

1. **בניית נתונים:** Actions → "Invest lab data" → Run workflow (שנים=20). כ-30–60 דקות ב-Yahoo. התוצאה: ענף `lab-data` + דוח ייחוס ב-Job Summary. רץ גם אוטומטית כל יום ראשון.
2. **האפליקציה:** `/invest/lab/` → Dashboard מראה את מצב הנתונים → "הרץ את דוגמת הייחוס" או בונה/ספרייה/AI.
3. **AI:** דורש `ANTHROPIC_API_KEY` (או binding ל-Workers AI) ב-Worker; בלעדיהם המפענח המקומי עובד.
4. **ללא דפדפן:** `node invest-api/scripts/lab-run.mjs --data lab-data-out --template top10-losers-1d --optimize --walk --md out.md`.
5. **בדיקות:** `node --test invest-api/tests/lab-*.test.mjs` (מנוע, אופטימיזציה, צינור נתונים, Worker).

## 6. אימות ידני (דרישה 15)

- `lab-engine.test.mjs` "עסקה ידנית": A יורדת 10% ביום 2 → נקנית בפתיחה ביום 3 ב-92 (לא ב-90!) → נמכרת בסגירה ב-95; 108 מניות; P&L 324$ בדיוק.
- אינווריאנט: הון סופי = הון התחלתי + Σ P&L העסקאות (כולל עלויות ודיבידנדים) — בכל מודל עלויות.
- Look-ahead: חיתוך הנתונים בתאריך D לא משנה אף עסקה שנסגרה לפני D, ולא את עקומת ההון.
- מסך "סורק היסטורי" מציג לכל יום את המועמדות, הערכים, הדירוג ומה קרה למחרת — אפשר לבדוק כל עסקה מול המספרים.

## 7. מה לא נבנה בגרסה זו (ומה הצעד הבא)

- פונדמנטלס point-in-time במעבדה (EDGAR קיים בפלטפורמה — שילוב במערך הנתונים הוא השלב הבא).
- Intraday / כניסה לפי שעה; מודל השפעת שוק; margin call; השאלה משתנה.
- יקומים מעבר ל-S&P 500 (דורשים ספק בתשלום — החלטת בעל הריפו).
- ייצוא PDF ייעודי (כרגע: תצוגת הדפסה של הדפדפן); Excel = קובץ טבלה שנפתח ב-Excel.
