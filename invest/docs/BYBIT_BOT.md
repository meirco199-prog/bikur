  (0.02% לפקודה ממתינה, 0.055% למיידית; נמדד מהעסקאות) גדולות מהתנועה עד היעד כשהרצועות צרות (0.05%–0.13% ביום שקט).
  לכן: **כניסה רק כשרוחב הרצועות ≥ 0.35% מהמחיר**, ופקודות הכניסה ב-**PostOnly** (תמיד בעמלה הנמוכה; אם המחיר כבר עבר את
  הרצועה — הפקודה נדחית). היעד נשאר GTC. הסימולציה במסך (`amit-rules.js`) נשארת על הכלל המקורי, כנקודת השוואה.
- **הגנות:** מגבלת הפסד יומית 1,000$ (ממומש + פתוח, יום לפי שעון ישראל) → סגירה, ביטול הכול ועצירה עד מחר. עסקה אחת בכל רגע.
  הבוט נוגע רק בפקודות שלו (`orderLinkId` שמתחיל ב-`amit-`). **הכתובת קבועה לחשבון הדמו (`api-demo.bybit.com`)** — אין בקוד דרך לחשבון אמיתי.
- **השרת:** Bybit חוסמת שרתים בארה"ב (גם את ה-runner של GitHub). הבוט רץ כשירות `bikur-bybit` על השרת של בעל הריפו (גרמניה),
  כמשתמש `bridge`. המפתחות רק שם: `/etc/bikur-bybit/bot.env` (640).
- **המפתח:** הרשאות מסחר בלבד — בלי Wallet (אין העברה או משיכה). נבדק 7/11: `Wallet: []`, תוקף עד 8/2/2027.
- **דיווח:** כל שעתיים (ומיד כשהבוט נעצר) — `POST /amit/bot` (סוד הגשר) → KV `amitbot:report` (לכל היותר פעם ב-20 דקות).
  מופיע במסך הקריפטו ובסיכום הקריפטו היומי בטלגרם, ליד הסימולציה — כך רואים אם המציאות תואמת.

## הפעלה ועצירה (Actions → "Bybit demo bot (Amit)" → Run workflow)
| פעולה | מה עושה |
|---|---|
| `install` | התקנה/עדכון מלא של שני הבוטים + בדיקת חיבור + הפעלה |
| `update` | משיכת קוד מ-main + ריסטארט |
| `status` / `logs` | מצב השירות ושורות אחרונות |
| `stop` | **עצירה מיידית:** קובץ STOP → הבוט מבטל את הפקודות שלו וסוגר פוזיציה, ואז השירות נעצר |
| `start` | מוחק את STOP ומפעיל (רק שירותים פעילים) |
| `stop1` | **בוט 1 בלבד:** קובץ STOP1 → בוט 1 מבטל פקודות וסוגר פוזיציה, השירות נעצר ומבוטל (גם `update`/`install` לא מחזירים אותו). בוט 2 ממשיך |
| `start1` | מוחק את STOP1 ומחזיר את בוט 1 |
| `stop3` / `start3` | **בוט 3 בלבד:** STOP3 → ביטול הפקודות שלו וסגירת הפוזיציות שלו, השירות נעצר ומבוטל / החזרה |
| `summary3` | סיכום בוט 3: עסקאות, נטו לפי מטבע, פוזיציות פתוחות, נתונים שנשמרו |

עצירה נוספת שלא תלויה בשום קוד: למחוק את המפתח `bot-demo` ב-Bybit (API Management).
